Purpose: confirm the statement is a valid proposition before the proof is checked against it. Every theorem goes through this step.

  1. The theorem's name is not already used.
  2. No universe parameter is listed twice.
  3. No unfilled holes (metavariables) or unbound variables (free variables).
  4. Every part type-checks: each constant exists and each function gets arguments of the right type. First CHECK call.
  5. The statement's type is Prop. INFER call.

If a test fails, the kernel stops before checking the proof. Steps 1–3 do not appear as rows.

Purpose: find the type of the proof, checking every part along the way. The final phase compares this type with the statement.

The kernel works from the outside of the proof inward. Each kind of term has a rule:

  • fun (x : A) => b: A must be a type. Add x : A to the context (CONTEXT). The type is ∀ x : A, B, where B is the type of b.
  • f a: the type of f must be a function type ∀ x : A, B. The type of a must match A (ARGUMENT, then DEFEQ). The type is B with a in place of x.
  • let h : T := v; b: T must be a type. The type of v must match T. Add h to the context. The type comes from b.
  • Constant or variable: its declared type.

The italic label on a call names the rule step that made it. To make two types match, DEFEQ may unfold definitions (UNFOLD) and simplify terms (WHNF). If any step fails, the kernel rejects the proof.

Purpose: confirm the proof proves the statement. One DEFEQ compares the proof's type, found in proof checking, with the statement.

  • They do not have to be written the same way. They must be equal after unfolding definitions and simplifying.
  • If they match, the theorem is accepted and added to the environment. If not, the kernel rejects it.
